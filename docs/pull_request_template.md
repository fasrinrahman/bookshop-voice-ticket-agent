# Pull Request Template

## 📖 Description
- Clearly explain the purpose of this PR.
- What problem does it solve or feature does it add?
- Link to any related issues (e.g., `Fixes #123`).

## 🛠 Implementation Details
- Summarize the technical changes made.
- Mention key files, functions, or modules affected.
- Note any architectural decisions or trade-offs.

## ✅ Testing
- Steps to reproduce the issue (if applicable).
- Steps to test the fix/feature.
- Include screenshots, logs, or test results if relevant.

## 📸 Screenshots / Visuals
- Add before/after screenshots, UI changes, or diagrams.
- If no visuals, state “N/A”.

## ⚠️ Risks & Considerations
- Potential side effects or breaking changes.
- Dependencies added or removed.
- Performance or security implications.

## 🔗 Related Resources
- Documentation updates required?
- Links to design docs, specs, or external references.

## 📋 Checklist
- [ ] Code follows project style guidelines
- [ ] Tests added or updated
- [ ] Documentation updated (if needed)
- [ ] CI/CD pipeline passes
- [ ] Reviewer(s) assigned
